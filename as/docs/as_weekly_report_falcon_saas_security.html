What is this doing?

Think of Falcon as the source of truth, the notebook as the sorter, Excel as the homework sheet, and ServiceNow as the place where a human can open a ticket draft.

Big Picture Flow

1

Login to Falcon API

The notebook uses your API client ID and secret to get a temporary access token.

2

Fetch alerts

It asks Falcon for configuration drift and integration failure alerts.

3

Add details

It fetches security check details and affected resources for each alert.

4

Build report

It creates summary, entity, error, and ServiceNow mapping tables.

5

Review drafts

You can cherry-pick missing-ticket alerts and open prefilled ServiceNow drafts.

Data source Falcon SaaS Security API is now the primary source.
Authentication OAuth2 client credentials, not the old Adaptive Shield token.
Safety ServiceNow draft cell pre-fills forms only. It does not submit tickets.

Step 1: Put These in .env

For your US-2 tenant, this is the expected setup:

API_SOURCE=falcon
FS_BASE_URL=https://api.us-2.crowdstrike.com
FS_CLIENT_ID=your_client_id
FS_CLIENT_SECRET=your_client_secret
Good base URL https://api.us-2.crowdstrike.com
Also accepted https://api.us-2.crowdstrike.com/saas-security/
The notebook cleans it up automatically.

Step 2: API Client Permission

The CrowdStrike API client needs read access for SaaS Security / Falcon Shield.

Ask for this permission SaaS Security (Falcon Shield): READ

If the notebook gets 403 Forbidden, the client probably exists but does not have this permission.

API Endpoints Used

POST /oauth2/token
GET /saas-security/entities/alerts/v3
GET /saas-security/entities/checks/v3
GET /saas-security/entities/check-affected/v3
GET /saas-security/entities/integrations/v3

Dates are sent as YYYY-MM-DD, because Falcon SaaS Security expects that format.

What Each Notebook Cell Does

  • Cell 1: Loads .env, reads Falcon settings, and prepares helper functions.
  • Cell 2: Gets alerts, security check details, affected resources, ServiceNow mappings, and quality checks.
  • Cell 3: Shows the alert UI with optional ServiceNow ticket context.
  • Cell 4: Lists alerts missing open tickets and opens selected ServiceNow draft forms with plain text description and HTML work notes.
  • Cell 5: Exports XLSX and CSV files.

Cell 4: ServiceNow Draft Behavior

Cell 4 is a helper for manual review. It opens draft incident forms and pre-fills fields, but it never saves, updates, or submits an incident.

Default people fields Caller is David Shih, assignment group is SN-informationSecurity, and assigned to is David Shih.
Description The description field gets easy-to-read plain text only, so ServiceNow does not show raw HTML there.
Work notes The work_notes field gets [code]...HTML...[/code], because that is where ServiceNow renders the HTML correctly.
Hidden memory Use Hide Selected to remember Falcon Shield alerts/checks you do not want to see again. The notebook stores that memory in .cache/as_weekly_report/snow_draft_hidden_alerts.json by default.

Troubleshooting Cheat Sheet

401

Meaning: Falcon did not accept the client credentials.

  • Check FS_CLIENT_ID.
  • Check FS_CLIENT_SECRET.
  • Check FS_BASE_URL.

403

Meaning: The client exists, but it lacks permission.

  • Ask for SaaS Security (Falcon Shield): READ.

No alerts

Meaning: The notebook worked, but there may be no matching alerts.

  • Increase LOOKBACK_DAYS.
  • Confirm alerts exist in Falcon.
  • Confirm you are using the correct Falcon cloud.

Stale rows

Meaning: The local cache may be showing older API results.

  • Disable cache for one run.
  • Or clear .cache/as_weekly_report.

Legacy Adaptive Shield Fallback

Only use this if you must run against the old API.

API_SOURCE=adaptive_shield
AS_API_KEY=your_legacy_token
AS_BASE_URL=https://api.adaptive-shield.com
New API clients should use Falcon SaaS Security. The old token path is kept only so older setups do not break immediately.
