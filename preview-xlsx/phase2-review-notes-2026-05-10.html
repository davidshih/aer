PriorityLocationIssueRecommendation
P0 package.json, test/runTest.js, test/security/rendering.test.ts Phase 2 makes npm run test red. The runner builds tests as CJS and keeps jsdom external; loading jsdom@29.1.1 then hits an ESM/CJS boundary error. Either pin a CJS-compatible DOM test dependency, switch the test runner to an ESM-compatible path, or replace jsdom with a dependency that works under the current CommonJS runner.
P1 src/parsers/xlsx.ts:35-48 The new ignoreNodes list mixes valid worksheet node names with names ExcelJS does not honor there, such as styles, themes, media, drawings, comments, tables, and pivotTables. The type cast hides this mismatch. Keep only ExcelJS-supported worksheet nodes, for example hyperlinks, picture, drawing, tableParts, conditionalFormatting, dataValidations, and extLst. Update wording so it does not claim unsupported parts are skipped.
P1 src/parsers/xlsx.ts:31-48 The implementation still uses the full ExcelJS workbook loader. The file-size cap is helpful, but row, column, and cell limits are applied after workbook load, so they are not true decompression or memory bounds. Keep the README threat-model honesty. If stronger DoS resistance is required, revisit streaming parsing or a pre-scan of XLSX zip entries.
P2 test/security/parser.test.ts Parser tests are well scoped: CSV formula-looking strings are preserved, HTML cell text survives as text, hyperlink targets are checked for leakage, and row/column limits are covered. After test runner is fixed, keep these tests in the regular npm run test path.
P2 test/security/rendering.test.ts Rendering tests correctly scope DOM checks to #grid and verify hostile strings become text nodes rather than a, img, script, or iframe elements. Good direction. It just needs a runner/dependency setup that actually executes.
P2 test/fixtures/build.js Fixture generator is deterministic and explicitly states no external content was copied. Small committed fixtures are reasonable for this phase. Keep the generator as the source of truth. Avoid adding huge generated files to the repo.

Summary

Phase 2 is conceptually on the right track: parser, CSP, and rendering tests are separated cleanly, and the fixtures are small and original. The immediate blocker is that the test runner is now red due to the jsdom ESM/CJS mismatch. Fix that before treating phase 2 as complete.
